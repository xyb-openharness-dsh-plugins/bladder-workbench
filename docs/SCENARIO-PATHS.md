# SCENARIO-PATHS · 小泉宝 UroPal · 膀胱癌

> 模板见 `templates/SCENARIO-PATHS.md`（**本项目同时是脚手架在调研设计阶段的增强来源**）。
> **位置**：`docs/SCENARIOS.md`（场景是什么）→ **本文件（从首页怎么走完它）** → `docs/UI-DESIGN.md`（界面长什么样）。
> **状态**：草案（phase1）。`G1` 签认前不冻结。

## 0 本项目的两个特殊约束

除模板 §0 的通用理由外，膀胱癌有两条让「操作路径」比家族其他癌种更关键：

1. **两条线走的是两套完全不同的路**（`DESIGN-01/02`）。同一个「留置针」在 NMIBC 是灌注、在 MIBC 是造口——首页入口、二级页签、字段集全都不一样。所以每条场景的路径**必须分线写**，不能写成一条通用路径分叉。
2. **主要录入人常常不是患者本人**（`DESIGN-09`，S14）。照护者接手时**不能先问患者**就得知道走到哪了。这意味着路径的终点不止「患者看到变化」，还要「换个人也能看到同样的变化」。

## 1 通用路径骨架

严格照模板 §1 的五步：**首页入口 → 进入即知所处 → 完成动作 → 得到产物 → 返回首页**。

本项目的首页（`看板`）固定承接四类回流，任何 P1 场景的终点必须落进其中之一：

| 首页区域 | 承接什么回流 | 原型现状 |
| --- | --- | --- |
| **A 分野闸门卡**（未选线时）/ **A′ 本线重点 hero**（已选线） | 选线、改线 | 已实现 |
| **B 当前阶段主卡**（灌注 / 改道 / 复查，随线切换） | 灌注进度、造口日记、复查排程 | 已实现 |
| **C 三张状态小卡**（灌注 / 下次膀胱镜 / 病理待澄清） | 三类关键状态的变更 | 已实现 |
| **D 待核对草稿计数 + 急症入口** | 新增草稿、急症路径 | 已实现 |

## 2 CRUD 交互模型落地

照模板 §2。本项目把「默认 AI 协助」落在**两个真实存在的地方**：

- **草稿区** = `病情整理 › 待核对草稿`。患者贴一段报告原文 → 系统出结构化候选 → 逐项「接受 / 改一下 / 不是这条」→ 才进 `病情档案`。**草稿永远标「未经核对」，与档案视觉分开。**
- **复诊准备 › 问题清单** = 说一句「我想问为什么还要再电切一次」→ 变成一条可编辑的问题，不必先想清楚该归到哪个字段。

**手工进阶路径只出现在三处**（对应模板 §2.4 的三种情况）：

| 位置 | 属于哪种情况 | 为什么手工 |
| --- | --- | --- |
| `尿流改道与造口 › 造口日记` | 批量重复录入 | 一次录一批（日期 + 型号 + 更换次数 + 渗漏 + 皮肤），型号从**耗材目录**选，不重打 |
| `膀胱灌注 › 本次记录` | 精确数值/日期 | 灌注日期与第几次容易歧义，表单预填后患者只做修正 |
| `生活与照护 › 性功能与亲密` | 私密内容 | 患者可能不愿对 AI 说，直接给本地输入框 |

**本项目明确不给手工表单的地方**（避免门槛上升）：
- 病理与分级 —— **一律走草稿核对**。理由是这里最容易出错（双分级、未见肌层），表单会诱导患者「自己挑一个值」，而核对界面能把原文摆在旁边。
- 治疗线 / 用药与周期 —— 走草稿。字段多且非患者术语。
- 临床试验收藏 —— 一键收藏，不需要表单。

## 3 逐场景操作路径（S01–S18）

`CRUD` 列说明本场景主要涉及哪几个动作（查 / 增 / 改 / 确认 / 删 / 导出）。

### S01 我到底在哪条线上 · P1

| 项 | 内容 |
| --- | --- |
| **首页入口** | 未选线：首页顶部**分野闸门卡**的三张选项（非肌层浸润 / 肌层浸润 / 我还确定不了）。已选线：hero 右上角「当前阶段」旁可回看与修改 |
| **进入即知所处** | 闸门卡上写明「这一步决定你看到的内容」；已选线时 hero 直接写当前线名与阶段 |
| **完成动作** | **查 + 改**。看三条线的白话说明 → 选一条 → 选完立刻看到属于这条线的看板（不是跳到别的页）。选「我还确定不了」也合法 |
| **得到产物** | 一条**留在首页的**分野状态（已选线 / 保持未定） |
| **返回首页** | **A → A′**：闸门卡换成该线 hero（本线重点 + 要长期做的三件事）；**B/C/D 三区内容随线重建**；页脚状态说明同步 |
| **CRUD 归类** | 改（可反复改，改动留痕） |
| **依赖** | 无。这是所有其他场景的前置 |

> **零倾向**：三条线的呈现不排序、不用倾向色、不写「建议选哪个」。选「保膀胱线」的按钮不比选「根治线」的更醒目。

### S02 病理报告逐字核对 · P1

| 项 | 内容 |
| --- | --- |
| **首页入口** | 首页 C 区「病理待澄清」小卡 → 直达 `我的分型与分期 › 病理与分级`；或 `病情整理 › 待核对草稿` |
| **进入即知所处** | 「病理与分级」页同时给出**原文栏与核对状态栏**，一眼看出哪几条已核对、哪几条还标着「未核实」 |
| **完成动作** | **增 + 确认**（默认 AI 协助）：把报告原文贴进草稿 → 系统逐词出候选（分级 / 浸润深度 / 有无肌层）→ 逐条「接受 / 改一下 / 不是这条」 |
| **得到产物** | 病理原文条目（**双分级原文并置**）+ 一份「待问医生」的点 |
| **返回首页** | **C 区「病理待澄清」卡**由「待核对」变为已核对条数；有未核对项时 D 区草稿计数 +1 |
| **CRUD 归类** | 增（草稿）、确认、改（原文不可改，改走新增修正） |
| **依赖** | 无 |

> **路径上的硬约束**：核对界面里「未见肌层」必须呈现为**「分期可能不完整」**，且旁边就给出「这点要问医生」——不能在页面的别处补一句「基本正常」。

### S03 下次灌注是第几次、为什么这次不做 · P1（仅 NMIBC）

| 项 | 内容 |
| --- | --- |
| **首页入口** | **B 区主卡「膀胱灌注 诱导 3/6 次已完成」**（NMIBC 线才会出现）；或左侧 `膀胱灌注` |
| **进入即知所处** | 主卡直接写「诱导 3/6 次 · 上次取消 · 下次 10-30」；进入后 `周期总览` 用**两段结构**（即刻 → 诱导 → 维持）呈现，不是等距序列 |
| **完成动作** | **查** → **改**：到 `本次记录` 确认这次做了 / 取消（精确日期走手工预填表单）；取消时必填原因 |
| **得到产物** | 更新后的周期表 + 中断原因记录 + 禁忌旗标（被拦时解释为「保护」。**不给补做建议**） |
| **返回首页** | **B 区主卡分子分母更新**（3/6 → 4/6），文案「上次取消 · 下次 …」随之改写；C 区「灌注」小卡同步 |
| **CRUD 归类** | 查（主）、改、增（一次性补录历史灌注） |
| **依赖** | S01 选 NMIBC。**MIBC 线下本卡不存在** |

### S04 复查前把心放下来 · P1

| 项 | 内容 |
| --- | --- |
| **首页入口** | **C 区「下次膀胱镜 2026-12-16」小卡** → `复查与膀胱镜` |
| **进入即知所处** | `复查排程` 首屏给出下次日期、间隔依据（**带 2022 版版本标**）与上次结论 |
| **完成动作** | **查 + 增**：看排程与上次结论；`疼痛与心情` 里记一次疼痛自评与心情（**感受区，与临床结论分开**）；`方式与麻醉` 记本次怎么做 |
| **得到产物** | 复查方式记录 + 疼痛/心情自评 + 排程中的下次日期 |
| **返回首页** | **C 区小卡**更新为本次记录（结论摘要 + 日期）；若已记感受，一图秀的疼痛序列多一个点 |
| **CRUD 归类** | 查、增（感受与方式）、改（排程改期） |
| **依赖** | 无（未选分野也可用——不确定属于哪条线时也需要复查） |

> **全站禁「终身」**：本路径涉及的所有间隔数字都必须标出版本来源，且任何地方不出现「终身随访」二字。

### S05 尿里那行「非典型细胞」 · P1

| 项 | 内容 |
| --- | --- |
| **首页入口** | `复查与膀胱镜 › 尿细胞学`；或从 C 区「下次膀胱镜」小卡的「尿细胞学同次送检」进入 |
| **进入即知所处** | 列表按日期倒序，每条**同时显示四态与标本类型**（自然尿 / 膀胱冲洗） |
| **完成动作** | **增 + 查**：贴化验单原文 → 草稿出候选 → 确认四态取值与标本类型 |
| **得到产物** | 尿检记录（四态 + 标本类型 + 报告原文 + 辅助检查） |
| **返回首页** | 不直接进首页固定区（**尿细胞学是分类变量，不进折线**）；若该条被标为需随访，则 C 区复查卡的说明文案更新 |
| **CRUD 归类** | 增、确认、查 |
| **依赖** | 无 |

> **零倾向着色**：四态**都不给倾向色**。「非典型」既不能渲染成阳性，也不能渲染成阴性——它在界面上就是一个中性的事实值。

### S06 为什么要再电切一次 · P1

| 项 | 内容 |
| --- | --- |
| **首页入口** | 左侧 `手术与 TURBT`；若已有未完成的二次电切计划，C 区会出现对应提示 |
| **进入即知所处** | `TURBT 序列` 按时间列出历次手术，每条标出**是否完全切除**与**是否二次** |
| **完成动作** | **增 + 查**：记一次 TURBT（日期 / 医院 / 是否完全切除 / 有无穿孔）；查历史序列理解为什么会有第二次 |
| **得到产物** | TURBT 序列 + 下一次手术的说明 |
| **返回首页** | C 区出现或更新「病理待澄清」卡的关联提示；若为 MIBC 且已安排根治术，B 区主卡切换为改道相关 |
| **CRUD 归类** | 增、查、改（补记是否完全切除） |
| **依赖** | 与 S02 共享病理结论 |

> **路径约束**：TURBT 是「切」不是「取活检」；二次电切是**同一手术线的下一事件**，路径上不新建档案、不出现「又一次确诊」。

### S09 「你肾不行，不能用顺铂」 · P1

| --- | --- |

### S14 换我来照顾，我得能接手 · P1
