## 1. 我代表谁

`[用户要求]` **两条主线人群并列，不是一条主一条次**：

- **A · NMIBC 保膀胱线**（非肌层浸润 Ta/T1/Tis，约占 3/4 患者）：中老年为主。治疗目标是**保住膀胱**，长期在做 TURBT、膀胱灌注（BCG/化疗）、每 3–6 个月膀胱镜复查，复发率 50–70%。他们的困难是"**又长出来了**"这件事的长期悬置，以及灌注副作用与断供。
- **B · MIBC 根治线**（肌层浸润 T2+）：已做或即将做根治性膀胱切除 + 尿流改道。他们的困难是**不可逆的身体重构**——带着造口或新膀胱重新学洗澡、穿衣、上班、亲密关系。
- **C · 主要照护者**（配偶/子女，以代记资料为主）：`[Agent 建议]` 在 B 线上照护者往往比患者本人更需要工具（术后早期换底盘、识别造口缺血、夜间集尿），因此**不是"帮患者打字的配角"，而是并列的记录主体**。`[待验证]` 代记比例究竟多高。

**潜在冲突**（必须显式处理，不能默认一致）：患者本人想少记、想保住膀胱；家属想多记、想尽快切。工作台只整理与呈现，**不替任何一方做倾向性表达**，也不把"保膀胱"写成默认正确选项。

## 4. 成功要改善的生活/就医结果

`[用户要求]`（写进 `completion`）：患者能用自己的话说清**自己在哪条线上、膀胱保不保得住要问什么、这次复查和灌注排到哪一步**；造口或新膀胱的照护者能接手记录而不丢信息。

`[Agent 建议]` 可观察的一期成功判据：
1. 患者拿着工作台产出的复诊摘要，能在门诊**用自己的话说出三个要问医生的问题**；
2. 换一个照护者接手，**不需要问患者**就能知道当前灌注周期排到第几周、下次膀胱镜是什么时候；
3. 出急症时（血块尿潴留 / BCG 全身感染 / 造口缺血 / 无尿腰痛），患者能在**30 秒内**找到"这算不算要立刻去"的判据与联系入口。

## 7. 医学约束与 AI 帮助边界

- 医学解释用**指南约束**（CUA/CSCO 膀胱癌诊疗指南，NCCN Bladder Cancer 仅作范围参照）；`[待验证]` 是否已取得最新版全文——未取得就写"未取得原文"，**不写"已按最新指南设计"**。
- 报告原文、通用解释、患者自述、专业判断**四层分开**；用户核对录入 ≠ 医学验证。
- 未知 / 未检测 / 未检出 / 失败 / 待出 / 不确定（如尿细胞学的"非典型/可疑"）**六态不可混同**，零值 ≠ 阴性。
- AI 价值：`[Agent 建议]` 整理、结合个人资料做带来源的通俗解释、把可讨论选项列清楚、草拟复诊问题。**不**给处置建议；AI 输出不自动沉淀为临床事实。

## 8. 功能取舍与一期/二期原则

`[用户要求]` **泌尿族实际先行者**：不等待前列腺癌 T0 的家族基线，泌尿族共享件（排尿与控尿、性功能、盆底、复查节奏）按**"待回填"**标注，等前列腺癌出来再对齐。

`[Agent 建议]` 取舍标准（按优先级）：
1. **只有膀胱癌才成立**的场景优先于通用能力——家族里已有的通用件（看板、病情整理、一图秀、营养、心理、复诊、收藏、试验、设置）照抄，不重新发明，也不许拿它冒充本病种需求。
2. **分野（NMIBC/MIBC）不清则一切不清**——所以它必须是一期第一个要解决的问题。
3. 能被**照护者接手**的记录优先于只能患者自记的记录。
4. 涉及身体形象/性/心理的模块**默认私密、可选分享**，不因为"记录更全"而默认打开。
5. 一期边界：`[用户要求]` 本轮严格停在 phase1（调研 → SPEC → schema 草案 → HTML demo → 文件体系），**不写业务代码**。
