# SCENARIOS · 小泉宝 UroPal · 膀胱癌

> **依据**：`prompts/NEW-CANCER-WORKBENCH.md §5`——场景细化是**核心交付**，追踪链必须闭合：
> `证据 E → 需求 N → 场景 S → 功能 F → 数据/交互 → 验收 A`
> **写法**：每条场景只写三要素——**触发**（决定入口在哪）→ **想完成的事**（患者要做成什么）→ **产物**（用户手里多了什么）。**不写功能名**。
> **筛选**：删掉"换成任何癌种都成立"的伪场景。
> **状态**：草案（phase1）；`G1` 签认前不冻结。

## 2 场景与模块的对应（不按 Tab 建事实表）

| 模块 F | 覆盖场景 | 事实实体（领域层，非页面副本） |
|---|---|---|
| `F-分野` | S01 | `DiagnosisAssertion`（分期/分级**多断言并列**，非单值字段） |
| `F-病理核对` | S02, S06 | `Document` / `PathologyFinding`（原文 + 核对状态） |
| `F-灌注` | S03 | `InstillationCourse`（多周期）+ `InstillationEvent`（计划/实际/中断原因）+ `Contraindication` |
| `F-复查` | S04 | `CystoscopyFollowUp`（排程 + 方式 + 结论 + 自评） |
| `F-尿检` | S05 | `UrineCytology`（标本类型 + 四态 + 原文） |
| `F-手术` | S06 | `SurgeryEvent`（TURBT / 根治术 / 二次电切，同一治疗线上的事件） |
| `F-改道` | S07, S08, S12 | `DiversionFact`（术式，不可逆）+ `StomaSupply`（目录）+ `MetabolicObservation` |
| `F-肾功` | S09, S11 | `RenalFunction`（序列）+ `UpperTractSurveillance` |
| `F-急症` | S10 | `UrgentSymptom`（四类 + 分级判据引用） |
| `F-私密` | S13 | `PrivateNote`（fail-closed） |
| `F-代记` | S14 | `Actor` / `Subject` 分离 + `Recorder` |
| `F-复诊` | S15 | `Question` / `Task` / `VisitSummary` |
| `F-试验` | S16 | `TrialSnapshot`（2026 快照，随包） |

> **口径**：`DiagnosisAssertion` 用**多断言并列**（借卵巢癌 `DiagnosisAssertion`），不用单值 `staging` 字段——因为同一患者可能同时存在"临床分期"与"病理分期"，且"G2"与"高级别"要**并列不换算**。

## 3 场景取舍（删掉了什么，为什么）

| 被删/降级的候选 | 理由 |
|---|---|
| "疾病百科/膀胱癌是什么" | **换成任何癌种都成立**，且患者教育材料已覆盖；工作台从现实任务进入，不从百科进入 |
| "记每日饮水量、每日排尿次数" | 通用健康打卡，无膀胱癌特异性；且与"少量多次饮水"的模糊建议绑定，易变成伪医学评分 |
| "自动算复发风险 / 危险度分层" | ⚠️ **判据原文是图片、未获取**；且属"替患者下结论"，越界。**不做** |
| "自动判断保膀胱 vs 根治" | 越界（`DESIGNER-BRIEF §8`）：工作台对"保还是切"**零倾向** |
| "造口照片 AI 识别是否正常" | 未验证的医学判断，且涉及隐私图像外发；**不做** |
| "膀胱癌分期算分器 / 生存期预测" | 家族已有先例明确不做（淋巴瘤 `D18` 不做 IPI/FLIPI 算分器）；本项目同样不做 |
| "灌注后憋尿时间的倒计时器" | ⚠️ **原文为图片、未获取**；给了就是编造医学操作指令。**待来源补齐后再议** |
