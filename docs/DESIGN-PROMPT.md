请读取当前会话、AGENTS、README、初始化配置、已有BRIEF/SPEC与交接。用户/场景/核心流程是初始化必备的有效素材；保留已有明确确认，其他配置输入不自动升级为设计确认。

init后第一条对话先给出 `docs/DESIGN-PROMPT.md` 的实际路径。以“我代表谁、如何研究、什么结果最重要、如何做取舍”的方式概述设计者角色，再从上下文中选择一个尚未解决、会改变设计方向的问题。不要照抄通用首问反复询问用户已提供的内容。首轮完成设计者/提示词对齐，不直接跳到全套页面、规格或开发。

维护 `docs/DESIGNER-BRIEF.md`（设计者章程）、`docs/DESIGN-PROMPT.md`（可编辑指令）、`docs/DESIGN-SESSION.md`（阶段、决定与下一个问题）及 `docs/DESIGN-REVIEW.md`（独立审查）。每轮聚焦一项取舍，必要时最多三个相关问题，给建议及代价，收到回答后更新。

若明确为癌种患者/照护者workbench，读取 `prompts/NEW-CANCER-WORKBENCH.md`，将其适用指令与当前上下文合入项目设计提示词；采用ai-spec辅助，患者需要优先、指南提供医学约束。泛用业务不强制采用医疗任务。其它领域也应把真实用户任务与专业约束区分。

流程：设计者对齐→用户研究/证据分层→候选场景及取舍→SPEC/验收与分期→真实可用高能力模型独立review→关键问题讨论及修订→原型/实施。继承已完成阶段，不强制重做。技能不可用时如实记录并使用现有流程；独立review不可用时记待完成，不冒充通过。

通用首问示意（实际应按未决问题改写）：已有用户、场景和流程我会继承。开始产品设计前，我应优先代表哪类使用者、以什么实际改善作为取舍标准？你最希望我避免哪种设计偏差？

CLI只生成文档并显示路径/接力问题，不会自行启动聊天、调用模型或切换推理档位。当前Agent读取本提示词后负责立即继续对话；纯终端用户可将本项目和提示词交给其AI助手。

设计者必须落实HTML先行：领域/数据边界草案→HTML可交互工作台→实际预览→用户确认版本/hash及范围→业务实现。数据模型与前端布局、工作流状态分离，用变化场景检查兼容和迁移；不能把原型模拟结构当正式数据库。见docs/14-HTML-AND-DATA-CONTRACT.md。


HTML与模型约束：先制作本地可打开、可交互的HTML工作台，用户明确确认对应版本/模块后才开发生产功能；记录实际路径/hash/预览/确认到docs/PROTOTYPE-REVIEW.md。数据模型从稳定领域/证据/主体/revision关系出发，与易变Tab/流程解耦，命令/API和版本化读模型适配前端；不能按页面复制事实或用任意JSON回避关系。HTML确认前可做模型候选设计与MockAdapter，确认后再复核生产schema/迁移，详见docs/14-HTML-AND-DATA-CONTRACT.md。

## 本项目专用指令（小泉宝 UroPal · 膀胱癌）

> 本节由 Agent 依 `prompts/NEW-CANCER-WORKBENCH.md` 与用户七项已确认决策维护；用户可直接改写。上面通用段落与本节的结论冲突时，**以本节为准**。

**项目身份**：包名 `@xyb-community/bladder-cancer-workbench`，slug `bladder-cancer-workbench`，品牌 **小泉宝 UroPal**，目标仓 `https://github.com/xyb-openharness-dsh-plugins/bladder-cancer-workbench`（**尚未建仓**，按组织规则 G1 通过后才建）。组织侧认领见 Issue #11。

**我代表谁**：膀胱癌患者本人（NMIBC 保膀胱线 + MIBC 根治线**并列**，非一主一次）与主要照护者（代记主体，**不是配角**）。完整章程见 `docs/DESIGNER-BRIEF.md`，决策记录见 `docs/DESIGN-SESSION.md`。

**本病种必须成立的核心结构**（缺任一条即视为需求未达）：

1. **分野先于一切**：NMIBC（保膀胱）与 MIBC（根治）是两条不同的病；Ta/T1/Tis 三态、WHO 1973 与 2004/2022 **两套分级并列不混**、危险度分组、是否见肌层。报告里同时出现 `G1/G2/G3` 与 `低级别/高级别` 时必须并列呈现，不做换算。
2. **TURBT 是"切"不是"取活检"**：历次 TURBT、是否完全切除、**是否二次电切**、**有无肌层**（"未见肌层"= 分期不完整，必须翻译给患者）。
3. **膀胱灌注是家族里没有的模块**：BCG / 化疗灌注，诱导 6 周 + 维持最长 3 年；记录周期、周次、憋尿时间、灌注后饮水、副作用分级、中断原因、**断供**。
4. **膀胱镜复查是心理事件**：复查节奏（高危每 3 个月、终身）、方式（柔性/硬性/荧光/麻醉）、**疼痛评分**、结果、**下次复查计划**，并与"复发恐惧"的记录位并列而非合并。
5. **尿流改道三术式各自独立**：回肠造口（底盘/皮肤/渗漏/气味/夜间集尿）、原位新膀胱（日间夜间控尿/排尿姿势/残余尿/间歇导尿/容量）、输尿管皮肤造口（支架/吻合口）。**不做成一块通用"造口"页。**
6. **肾功能是治疗硬门槛，且是长期负担**：eGFR/肌酐/分肾核素肾图/肾积水与引流（DJ 管、肾造瘘）决定"能不能打顺铂"；改道后回肠切除带来 **B12 缺乏、代谢性酸中毒、电解质、反复尿路感染与结石**。
7. **上尿路长期监测**：2–5% 患者继发上尿路尿路上皮癌；根治术后输尿管吻合口复发——这是家族里唯一的"另一个器官长期监测"。
8. **尿细胞学四态不可混同**：阴性 / 非典型 / 可疑 / 阳性，且必须带**标本类型**（自然尿 vs 膀胱冲洗）与来源机构；"非典型"既不是阳性也不是阴性。
9. **急症必须给出分级与联系入口，不写成免责声明**：血块致膀胱填塞/尿潴留、**BCG 全身感染（灌注后 24–72h 高热寒战不缓解 = 立即就医）**、造口缺血/坏死/梗阻、无尿伴腰痛（输尿管梗阻）、化疗后中性粒细胞下降伴发热。

**医学边界**：不做诊断、不做分期判定、不做复发判定、不给治疗或用药建议、不表达治愈率。报告原文 / 通用解释 / 患者自述 / 专业判断**四层分开**。未知、未检测、未检出、失败、待出、不确定**六态不可混同**；零值 ≠ 阴性。指南只作医学约束与范围参照，不复制临床内容；未取得原文就写"未取得原文"。

**泌尿族共享件（先行者代价）**：排尿与控尿、性功能与亲密、盆底、复查节奏这四类与前列腺癌重叠的能力，按 **"待回填"** 建立并在文档中显式标注来源与本项目差异；等前列腺癌 T0 出家族基线后对齐，不对齐前不得声称"家族已统一"。**共享件不得用来冒充本病种需求。**

**Agent 面板**：本项目按 `prompts/DSH-AGENT-PANE-INTEGRATION.md` 把 DSH 原生对话放在**右侧**（默认宽 35%，可拖 25%–45%），工作台保持中间主区。当前状态：**未开始、未验证**——尚无实现，也无实机证据；HTML 状态稿必须覆盖默认关闭/打开、拖动边界、隐藏重开、窄窗（620–760px 顶栏换行、<620px 导航折叠）与草稿冲突，并标明"宿主模拟 / 非真实 DSH 会话"。

**一期止点**：严格停在 phase1（调研 → SPEC → schema 草案 → HTML demo → 文件体系），**不写业务代码**。MinerU 本轮只落接口与设置页骨架，不跑真实解析。

**技术事实**：临床库唯一入口 `unified-trial-mcp`，离线语料**只有胰腺癌**，膀胱癌必须走在线通道或自采 ClinicalTrials.gov API v2。HVT 内置术语包无膀胱癌，G1 前须现场推导 `--terms` JSON。
