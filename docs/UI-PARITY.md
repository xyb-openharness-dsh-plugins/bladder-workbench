## 5 变化承受能力走查（**设计时就要能改**）

按 `docs/SPEC.md` 的"数据模型演进关口"做三种变化走查，看**哪些必须动事实表、哪些只动读模型**：

| 变化 | 事实层 | 读模型/前端 | 走查结论 |
| --- | --- | --- | --- |
| **改导航**（把一个页签挪到另一页） | 不动 | 只改 `NAV` + 分发函数 | ✅ 页签内容按名字分发，**但**：同一份页签名清单写在 `data.js` 与 `app.js` 两处 → **必然漂移**（已踩过两次）。已加"每个名字都有非空分支"断言兜底 |
| **加一个字段**（如病理再加一项） | 加列走迁移 | 加渲染行 | ✅ 但现在**没有自动断言**新字段一定被渲染出——靠人工走查 |
| **新指标**（不在现有 7 项里） | `metric_definitions` **插行**，不迁移 | 自动出现在指标卡与一图秀 | ✅ 这是设计目标；**未实测** |
| **跳过/重开一个步骤**（如先不改道、后补录） | 状态字段 + `change_log` | 不删历史行 | ✅ 结构支持；**原型只演示了术式改动留痕** |
| **换一家医院**（改了检验机构/方法） | 不动 | 按「机构·方法」拆可比组、**段内才连线** | ✅ 已实现（肌酐 2026-10-08 拆成 2 组） |

**⚠️ 走查暴露的薄弱点**：
1. 「同一份清单写在两个文件里」这个结构性问题只靠**断言**兜底，没有从根上消灭（`data.js` 与 `app.js` 各存一份页签名）。
2. 「新增字段自动渲染」**没有断言**，是纯人工检查。

这两条记进 `docs/DESIGN-REVIEW.md` 的问题清单。
